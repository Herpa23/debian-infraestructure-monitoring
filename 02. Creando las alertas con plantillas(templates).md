### 1. ¿Qué son las reglas de alerta en Prometheus? (`alert.rules.yml`)

Las reglas de alerta le indican a Prometheus qué métricas evaluar y cuándo disparar una condición de alerta. Estas reglas se evalúan periódicamente y, si se cumple la condición durante el tiempo especificado (`for`), Prometheus envía la alerta a **Alertmanager**.


### 2. Creación y estructuración de plantillas de alertas (`alert.rules.yml`)

Para ahorrar tiempo y aplicar mejores prácticas de la industria sin tener que redactar todas las métricas y expresiones de Prometheus desde cero, podemos apalancarnos en la comunidad y recursos oficiales.

- **El recurso clave (Awesome Prometheus Alerts):** Puedes consultar el repositorio de referencia [Awesome Prometheus Alerts](https://samber.github.io/awesome-prometheus-alerts/) (o similares curados por la comunidad). Este sitio web agrupa plantillas listas para producción para casi cualquier componente (Linux/Node Exporter, Docker, Kubernetes, bases de datos, etc.).
    
- **Metodología de trabajo recomendada:**
    
    1. **Buscar el objetivo:** Entra a la guía y busca la alerta que necesitas (por ejemplo, uso excesivo de CPU, disco lleno o caída de servicio).
        
    2. **Copiar y adaptar:** Copia la estructura base de la regla y ajústala según tus umbrales (por ejemplo, cambiar el tiempo en el parámetro `for` o el porcentaje de carga).
        
    3. **Alinear severidades:** Asegúrate de que las etiquetas (`labels`) incluyan la severidad (`critical`, `warning`, `info`) para que Alertmanager se encargue de enrutarlas automáticamente al hilo correcto de Telegram.

### 3. Estructura Modular y Descarga de Alertas en el Nodo (`debian-monitor`)

Para mantener una separación limpia y profesional orientada a un perfil de SysAdmin, organizaremos las reglas en dos directorios lógicos dentro de `/opt/monitoring/rules/`:

- `debian-infra/`: Métricas del sistema operativo, contenedores y servicios del host.
    
- `observability/`: Salud interna del propio stack de monitoreo (Prometheus, Grafana Alloy y Loki).
    

**1.Crear el árbol de directorios modular:**

Ejecuta los siguientes comandos en tu servidor para estructurar las carpetas:

```bash
cd /opt/monitoring
mkdir -p rules/debian-infra rules/observability
```

_Verification:_ Ejecuta `ls -lah rules/` y corrobora que existan ambos subdirectorios.

**2.Descargar las reglas de infraestructura (debian-infra):**

Ingresa al directorio e incorpora las plantillas oficiales optimizadas para Linux y contenedores:

```bash
cd /opt/monitoring/rules/debian-infra
wget -O host-and-hardware.rules.yml https://raw.githubusercontent.com/samber/awesome-prometheus-alerts/master/dist/rules/host-and-hardware/host-and-hardware.rules.yml
wget -O docker-containers.rules.yml https://raw.githubusercontent.com/samber/awesome-prometheus-alerts/master/dist/rules/docker/docker.rules.yml
wget -O systemd-services.rules.yml https://raw.githubusercontent.com/samber/awesome-prometheus-alerts/master/dist/rules/systemd/systemd.rules.yml
```

**3.Descargar las reglas del stack de observabilidad (observability):**

Muévete a la segunda carpeta y descarga las reglas para vigilar el motor de métricas, el colector y los logs:

```bash
cd /opt/monitoring/rules/observability
wget -O prometheus-self-monitoring.yml https://raw.githubusercontent.com/samber/awesome-prometheus-alerts/master/dist/rules/prometheus/prometheus.rules.yml
wget -O grafana-alloy.yml https://raw.githubusercontent.com/samber/awesome-prometheus-alerts/master/dist/rules/grafana-alloy/grafana-alloy.rules.yml
wget -O loki.yml https://raw.githubusercontent.com/samber/awesome-prometheus-alerts/mast
```

### 4. Integración con Prometheus (`docker-compose.yml` y `prometheus.yml`)

Para que Prometheus reconozca y evalúe estas reglas de forma automática, debemos exponer el directorio en los volúmenes del contenedor y declarar las rutas explícitamente en la configuración.

#### A. Ajuste del volumen en `docker-compose.yml`

Asegúrate de que el servicio de Prometheus mapee la carpeta de reglas local hacia el directorio interno del contenedor:


```yaml
services:
  prometheus:
    image: prom/prometheus:latest
    container_name: prometheus
    restart: unless-stopped
    ports:
      - "9090:9090"
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
      - ./rules:/etc/prometheus/rules
      - prometheus_data:/prometheus
    command:
      - '--config.file=/etc/prometheus/prometheus.yml'
      - '--web.enable-remote-write-receiver'
    networks:
      - monitoring_net
```

_Aquí se agregó un volumen de donde prometheus va a poder trabajar con las alertas_

#### B. Declaración de rutas en `prometheus.yml` y Alertmanager

Configura el intervalo de evaluación global e indica las rutas explícitas de los archivos de reglas y a alertmanager para poder recibir las alertas:

```yaml
global:
  scrape_interval: 15s
  evaluation_interval: 15s

alerting: 
  alertmanagers: 
  - static_configs: 
  - targets: ['alertmanager:9093']

rule_files:
  - 'rules/debian-infra/*.yml'
  - 'rules/observability/*.yml'

scrape_configs:
  - job_name: 'prometheus'
    static_configs:
      - targets: ['localhost:9090']
```

### 5. Despliegue y Validación Final

**1.Reiniciar el stack de monitoreo:**

Aplica los cambios ejecutando el reinicio del contenedor desde tu directorio de trabajo:

```bash
cd /opt/monitoring
docker compose down
docker compose up -d
```

**2.Verificar el arranque del Rule Manager:**

Confirma en los registros que Prometheus cargó las reglas sin errores de sintaxis:

```bash
docker logs prometheus
```

_Resultado esperado:_ Debes visualizar el mensaje `Starting rule manager...` indicando que todas las reglas de infraestructura y observabilidad están operativas.
