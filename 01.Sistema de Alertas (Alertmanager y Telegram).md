### 1. Preparación previa en Telegram (Grupo con Tópicos y Bot)

Antes de configurar las alertas en el servidor, es necesario preparar el canal de comunicación en Telegram para separar los mensajes por niveles de severidad:

- **Crear un grupo con Tópicos (Topics):**
    
    1. Crea un nuevo grupo en Telegram y asegúrate de habilitar la opción de **Temas** (_Topics_) en la configuración del grupo.
        
    2. Crea un hilo o tema específico para cada nivel de prioridad:
        
        - 🔴 **Critics** (Destinado para alertas críticas).
            
        - ⚠️ **Warnings** (Destinado para advertencias).
            
        - ℹ️ **Info/System** (Destinado para información y eventos del sistema).
            
- **Crear el bot de Telegram:**
    
    1. Interactúa con `@BotFather` en Telegram para registrar un nuevo bot único (por ejemplo, `@homelab_alert_bot`).
    
    2. Copia y guarda el **HTTP API Token** proporcionado (ejemplo: `7492816350:AAH_x9kLp2mN8qR4vT6yW1zB3cD5eF7gH9I`).
    
- **Agregar el bot al grupo:**
    
    1. Entra a las propiedades del grupo de Telegram, ve a la sección de miembros y añade a tu bot (`@homelab_alert_bot`).
    
    2. Con esto, el bot tendrá permisos para enviar notificaciones dentro del grupo.
        
- **Identificadores clave obtenidos que nos van a servir para armar nuestro archivo `alertamanger.yml`:**
    
    - **Chat ID del grupo:** `-1004372998816`
    
    - **IDs de los hilos (_Message Thread IDs_):**
        
        - Critics: `2`
            
        - Warnings: `4`
            
        - Info/System: `5`



### 2. Actualización del `docker-compose.yml`

Para integrar Alertmanager al entorno de monitoreo ubicado en `/opt/monitoring`, realizamos los siguientes pasos:

**A. Detener temporalmente el entorno:** Ingresamos al directorio de trabajo y detenemos los contenedores activos para poder modificar la infraestructura:

```bash
cd /opt/monitoring
docker compose down
```

_Este comando apaga los servicios de forma limpia permitiendo aplicar la nueva configuración sin conflictos de contenedores huérfanos._

**B. Agregar el servicio de Alertmanager:** Modificamos el archivo `docker-compose.yml` añadiendo el bloque de Alertmanager dentro de los `services` para que trabaje en red junto con Prometheus:

Se añade este bloque dentro de los `services` de tu archivo `/opt/monitoring/docker-compose.yml`:

```yaml
  alertmanager:
    image: prom/alertmanager:latest
    container_name: alertmanager
    restart: unless-stopped
    ports:
      - "9093:9093"
    volumes:
      - ./alertmanager.yml:/etc/alertmanager/alertmanager.yml
    networks:
      - monitoring_net
```

**C. Levantar nuevamente el stack:**
Aplicamos los cambios y ponemos en marcha los servicios ejecutando:

```bash
docker compose up -d
```

### 3. Creación del archivo de configuración de Alertmanager (`alertmanager.yml`)

Crea un nuevo archivo en tu directorio de trabajo para configurar las credenciales de tu bot de Telegram y la estructura del mensaje de alerta:


```bash
nano /opt/monitoring/alertmanager.yml
```


### 4. Configuración del enrutamiento por severidad e hilos en `alertmanager.yml`

Configuramos el archivo `/opt/monitoring/alertmanager.yml` para utilizar un único bot de Telegram (`@homelab_alert_bot`) y enrutar las alertas hacia diferentes temas (_threads_) del mismo grupo de Telegram según su etiqueta de severidad (`critical`, `warning`, `info`):

```yaml
---
global:
  resolve_timeout: 5m

route:
  group_by: ['alertname', 'severity']
  group_wait: 30s
  group_interval: 5m
  repeat_interval: 4h
  receiver: 'info-receiver'
  routes:
    - match:
        severity: critical
      receiver: 'critical-receiver'
      group_wait: 10s
      repeat_interval: 1h
    - match:
        severity: warning
      receiver: 'warning-receiver'
      group_wait: 30s
      repeat_interval: 2h

receivers:
  - name: 'critical-receiver'
    telegram_configs:
      - bot_token: 'token-telegram-example'
        chat_id: -1004372998816
        message_thread_id: 2
        parse_mode: 'HTML'
        message: >
          <b>🔥 ALERTA CRÍTICA 🔥</b>
          <b>Nombre:</b> {{ .GroupLabels.alertname }}
          <b>Estado:</b> {{ .Status }}
          <b>Descripción:</b> {{ .CommonAnnotations.description }}

  - name: 'warning-receiver'
    telegram_configs:
      - bot_token: 'token-telegram-example'
        chat_id: -1004372998816
        message_thread_id: 4
        parse_mode: 'HTML'
        message: >
          <b>⚠️ ADVERTENCIA ⚠️</b>
          <b>Nombre:</b> {{ .GroupLabels.alertname }}
          <b>Estado:</b> {{ .Status }}
          <b>Descripción:</b> {{ .CommonAnnotations.description }}

  - name: 'info-receiver'
    telegram_configs:
      - bot_token: 'token-telegram-example'
        chat_id: -1004372998816
        message_thread_id: 5
        parse_mode: 'HTML'
        message: >
          <b>ℹ️ INFORMACIÓN ℹ️</b>
          <b>Nombre:</b> {{ .GroupLabels.alertname }}
          <b>Estado:</b> {{ .Status }}
          <b>Descripción:</b> {{ .CommonAnnotations.description }}
```

### 5. Validación y prueba de integración con la API v2

Para verificar que el contenedor procesa las alertas correctamente y las envía al hilo correspondiente en Telegram (`message_thread_id: 2` para críticos), ejecutamos una petición POST simulada desde la terminal usando la API v2 de Alertmanager:

```bash
curl -H "Content-Type: application/json" -d '[
  {
    "labels": {
      "alertname": "TestCriticalAlert",
      "severity": "critical"
    },
    "annotations": {
      "description": "Verificando enrutamiento al hilo de criticos correctamente."
    }
  }
]' http://localhost:9093/api/v2/alerts
```

- **Nota clave:** Las versiones recientes de Alertmanager (>= 0.27.0) deprecian por completo la API v1, por lo que siempre se debe apuntar al endpoint `/api/v2/alerts`.
